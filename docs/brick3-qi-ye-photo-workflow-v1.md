# 《磚3》祁野：照片生成、對話與遊戲配置規則

適用分支：`feature/character-autonomy-v3`。角色代碼：`qi_ye`。本文件規範**創作期**的圖片與事件配置；遊戲內僅讀取預先上傳的素材，不因玩家開啟聊天室即時重新生成。

## 固定角色與視覺錨點

祁野，23 歲，祁家次子，家境優渥；與玩家因緣際會認識，初期好感度隱藏且為 0。惡犬 75%＋野狼 25%，張揚、叛逆、直球、好勝、嘴硬，具備自己的原則和生活。籃球、街頭運動、攝影、設計與家族活動均可成為拍攝題材，但不可每張都有豪車、名錶或豪宅。初識階段不會直接告白或強烈追求。

**每次生成人物照片須先取得實際確立外貌的原圖**（正面、側面、髮型、表情、耳飾、唇飾及體態），不可僅依角色名字猜測人物長相。本專案已有 `public/characters/qi-ye.png`，但是否等同作者在對話中確認的多視角設定板，須實際核對後才可當作相同參考。角色可換衣服、光影、表情，但不可隨機換臉。拍攝者及入鏡 NPC 必須確實存在於場景。

## 日常照片風格與拍攝動機

- 核心：**隨性惡犬，想拍就拍，想傳就傳**；有自己的家族、朋友、興趣、行程，並非全為玩家服務。
- 可拍精選自拍、狼狽照、運動後、設計桌面、食物、街景、聚會、安靜時刻或攝影作品；有時搞怪、有時隨手亂拍。
- 手機攝影感為主：低角度、不對稱、偶爾廣角、逆光、動態模糊皆合理；不固定專業棚拍、冷臉、刻意性感。懂攝影不代表隨手拍都完美。
- 長期題材參考：運動與活動 30%、自拍與穿搭 25%、朋友外出 20%、攝影設計 15%、日常其他 10%。**不作每日配額或強制觸發**。可整天沒有照片。
- 共同外出且確有適合拍照事件時，長期可參考：自己拍 50%、同行 NPC 幫拍 20%、與**已存在同行 NPC** 合照 30%。禁止憑空生成朋友及玩家與 NPC 合照。
- 先確認日程、地點、事件、情緒、分享動機，再決定拍照。**拍下、決定分享、真正發送**是三個不同狀態；可拍後不傳。玩家未打開聊天室仍可收到已排定訊息；重新開啟只顯示已發生歷史，不產生新照片。

## 分工：玩家只負責批次上傳照片

作者已確認簡化流程：**玩家僅負責將已準備好、已命名的 WebP 圖片批次上傳 GitHub**；不負責建立 JSON、修改程式、分鏡事件、撰寫選項或手動操作相簿解鎖設定。

創作助手負責：

1. 依祁野視覺基準規劃、生成照片，將每張裁切、轉為 WebP、按照 `qi_ye_事件名稱_照片序號.webp` 命名，確保檔案名稱與事件 JSON 完全一致。
2. 整理一批可以直接上傳的圖片（可另附 ZIP 供下載；**必須解壓縮後再選取多張圖片上傳，不能把 ZIP 本身視為照片素材**）。
3. 提供唯一的上傳資料夾連結：`https://github.com/youhoie0611-oss/FoundPhone-Studio/upload/feature/character-autonomy-v3/public/story-photos/qi_ye`。
4. 同時編寫聊天文案、四種分歧、角色回覆、事件條件、照片狀態、相簿解鎖和後續事件；將可提交的文字／JSON 配置提交至指定開發分支。
5. 玩家上傳照片後，檢查 GitHub 是否存在預期的 WebP 檔，確認檔名與 JSON 路徑一致，再進行適當的遊戲事件整合與可執行測試。
6. 不得把「配置已提交」冒稱「圖片已上傳」或「遊戲已測試通過」。如未能執行本機 build/test，明確標明未驗證。

玩家批次上傳只需：打開上傳連結 → 多選／拖入所有 WebP → 按一次 `Commit changes`。不需要逐張 Commit；也不需人工更名、撰寫事件 JSON 或改程式。

## 照片檔案與玩家手動上傳

- 圖片格式：`webp`；固定資料夾：`public/story-photos/qi_ye/`。
- 命名：`qi_ye_事件名稱_照片序號.webp`，事件名稱採小寫英文與底線；不得修改已被事件引用的原圖。
- 實際圖片由玩家手動上傳至 GitHub，不由文字配置提交冒充圖片已存在。
- 每次生成回覆須附：**完整檔名、用途、目標檔案路徑、GitHub 上傳資料夾連結、照片拍攝者與入鏡角色、劇情條件、聊天訊息、四種不同玩家選項、每個選項的反應與分歧、相簿解鎖、後續事件、可提交 JSON**。
- GitHub 上傳連結：`https://github.com/youhoie0611-oss/FoundPhone-Studio/upload/feature/character-autonomy-v3/public/story-photos/qi_ye`。
- GitHub 資料夾連結：`https://github.com/youhoie0611-oss/FoundPhone-Studio/tree/feature/character-autonomy-v3/public/story-photos/qi_ye`。
- 沒有上傳圖片時標註「圖片尚未上傳」，不得說素材已接入遊戲或相簿已可解鎖。

## JSON 規格與交付

以同分支 `docs/brick3-photo-events-v1.json` 的 `events[]` 為核心格式：

- `eventId`、`characterId: "qi_ye"`、`characterName: "祁野"`、`type`、`trigger`、`message`、`choices[4]`、`images[]`。
- 每個 `images[]` 要有固定 `assetId`、`filename`、`path`、`usage`、`unlock`、`visualPrompt`。
- 每個選項至少區分 **正常詢問／調侃／關心／冷淡**，各自有**不相同**、不預設玩家心情的回應，且後續依選擇合理分歧。
- 補充的 `branchResponses`、`albumRules`、`followUpEvents`、`captureMetadata` 是**作者配置擴充欄位**，須由正式事件引擎轉譯；寫進文件不代表運行時自動生效。
- 相簿：事件真的發生、照片真的送達（或其他明確符合規格的事件）、素材檔存在才能解鎖，否則保留為未解鎖；不能因邀約或僅生成素材而解鎖。
- 條件至少檢查當日 NPC 行程、地點、已知資訊、是否曾觸發、與玩家關係及照片素材是否可用；不得預設玩家參加活動、答應邀約或開始交往。
- 私訊照片不因出現在 KKT 而被其他 NPC 自動看到；公開動態與私人訊息須區分可見權限。

## 祁野對話與玩家自主

初期可以用「路過這裡。夜景還行。」搭配自己拍的城市夜景，但不必故作霸道，也不需要刻意撩。正常提問先回答問題，調侃可玩笑回嘴，關心可接受或表明自己行程，冷淡則自然收尾。

不可永遠使用「喂」、「怎樣」、「不然呢」或大量連續訊息，不得無視玩家選項。玩家忙時自然暫停，祁野照常生活。後續照片可連到家族合作、聯姻傳聞或朋友事件，但人物與時間線須確有根據；**公開合照引起疑問不等於證實戀愛**。禁止侵犯玩家自主權、用家世資源控制玩家、要求玩家傳照片或擅自編造親密情節。

## 手機照片尺寸與品質（2026-11-06 確認）

本規則適用於祁野後續的所有生成批次：

- **KKT 一般手機直式照片**：預設 **3:4**，建議交付 `1080×1440` WebP。
- **KKT 橫向手機照片**：確實適合橫幅構圖時，使用 **4:3**，建議 `1440×1080` WebP。
- **Instagram Story**：使用 **9:16**，建議 `1080×1920` WebP。
- **Instagram Post**：建議 **4:5**（`1080×1350`）或 **1:1**（`1080×1080`），以實際場景為準。
- **不可把五欄橫向拼貼圖直接裁成十張寬橫照片**；每張應是獨立、完整的真實手機攝影構圖，無拼圖邊框、資訊表、文字標籤、UI。
- 交付前應使用程式讀取並驗證十張的實際像素尺寸、WebP 格式與完整檔名，保持與 JSON 事件圖片路徑一致；10 張一次 ZIP（ZIP 解壓後全選 10 張上傳）。
- **不得以單純放大冒稱原生高解析**。若因現有拼圖裁切來源而造成素材細節不足，須明示，未來應優先逐張原生直式生成或重製。
- 不因修改照片構圖、像素尺寸而更換原已提交的 `assetId`、`eventId`、聊天選項或既有角色關係。

本次 batch01 初版約 900×600 橫圖，已另製作 **1080×1440 3:4 直式 WebP 的修正版十張**供作者批次上傳。修正版仍由拼圖生成來源重裁及重採樣，屬網頁遊戲用預覽品質，**不是原生 1080×1440 光學細節**。GitHub 上的圖片須由作者手動上傳後才算實際存在。


## 高畫質單張與正常自拍距離（2026-11-06 調整）

作者確認：一般自拍不應像貼著鏡頭；祁野**只有故意搞怪時**，才會把手機放得很近。後續生成需讓人物與所到場所並重，並提高「不常去的體驗場所／戶外探險」占比。

- 每張照片必須**獨立生成成一張真正的手機照片**，不產生 5×6 聯絡表、拼貼、資訊圖、編號、邊框或 UI。
- KKT 正常自拍：前鏡頭距臉約 70–100 cm（自然手臂長度），露出上半身／腰部與環境。臉在畫面占比**不超過約 35%**，保留場景至少約一半；鏡子自拍可拍到全身。非自拍可由祁野本人手機 POV 拍風景、活動或物件。
- **只有搞怪自拍**可以故意使用極近鏡頭、廣角變形、誇張表情。狼狽、安靜、疲憊不是近距離特寫的理由。
- 景點可以更不日常：合法營運的卡丁車館、室內滑雪場、洞穴觀光步道、玻璃觀景步道、夜間水族館、鏡面迷宮、風洞飛行、山區滑索、纜車、舊工業建築改造展、天文觀測等；確保安全與合理自拍機位，絕不在開車、滑索滑行、攀爬途中使用手持手機。
- 遊玩事件必須由**祁野實際獨立行程**、時間、地點和情緒決定；未確認的地點只能作為候選故事，不可擅自變成既定玩家共同回憶。
- 每張以原生可讀的照片輸出；優先手機直式 3:4，必要橫幅 4:3；IG Story 9:16、Post 4:5。**不得把拼貼裁切後放大當成高畫質成品**。
- 每張要存有唯一 `assetId`、檔名、攝影者、內容人物、衣服、拍攝場景、分享條件、後續事件和四種不同玩家回答。原圖只能引用，不能在玩家開啟聊天室時重新生成。
- 作者這次要求重製 30 張。重製方案位於 `docs/brick3-qi-ye-photo-batch02-30-events.json`，在逐張照片通過真正獨立畫質檢查並由玩家上傳之前，**只能標記未生成／未上傳，不能送入正式遊戲使用**。
- 上傳仍由玩家負責，**一次上傳一批照片**；JSON、劇情、遊戲整合、路徑驗證由開發助手處理。
