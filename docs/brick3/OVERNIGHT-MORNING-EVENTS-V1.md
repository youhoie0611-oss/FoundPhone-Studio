# 《磚3》原過夜系統延伸：隔日特殊事件 V1

狀態：新增劇情與實作規格；不得宣稱本文件本身已接入執行引擎。
適用分支：feature/character-autonomy-v3
優先級：附加規格，不覆蓋既有過夜事件、關係設定與 FoundPhone 核心功能。

## 一、既有過夜機制保留（依先前開發討論，實作需逐項核對）
- 雙向過夜邀約：玩家與 NPC 均可提出，雙方都可拒絕。
- 床伴關係可以不先交往；床伴轉正沿用既有隱藏好感門檻 70 與持續過夜條件，仍須雙方自願，不自動轉正。
- 秘密過夜與懷疑值機制保留；既有曝光門檻 100 不改動，不能憑空讓他人知情。
- 約會後可銜接留宿；不強制進入親密行為。
- 過夜照片沿用每次 3～5 張、玩家第一人稱手機照片的既有規則；照片必須有實際生成檔案才能展示，且須符合人物外貌、關係與情境。
- 上述為原討論要求，整合前應以目前程式和資料核實，若實作不同先記錄差異，不直接覆寫。

## 二、事件生命週期
1. 邀約：記錄邀請方、時間、地點、回答、雙方同意與各自行程。
2. 到場：只有玩家明確答應並實際到場才建立留宿紀錄。
3. 夜間：依現有過夜分支處理；擁抱、親吻及其他親密接觸分別確認同意。
4. 睡眠：跨日保存雙方位置、是否同房、尚未完成的對話與預定離開時間。
5. 早晨：根據角色、關係類型、前夜選擇、工作日程挑選事件，不以好感度單獨決定。
6. 離開後：可排程中午／傍晚 KKT 延續，玩家未開聊天室也會正常送達。
7. 長期：累積生活習慣與關係記憶，不強制同居或交往。

## 三、五位角色專屬早晨候選
- 沈硯舟《再睡五分鐘》：攝影／上課／球賽前的早餐與賴床；不會為玩家無理由曠課。
- 裴知聿《你以前也這樣》：前任共同生活細節與現在關係的矛盾；陰濕重力系，依戀、不安、希望多留一會，但尊重拒絕；床伴、復合、地下關係有不同反應。
- 祁野《誰說要留妳》：嘴硬的早餐邀請、借衣服與家族行程衝突；不能擅自替玩家取消行程。
- 顧時安《兩人份的早餐》：生活節奏、料理、工作與私人界線；不把成熟寫成無條件退讓。
- 陸沉川《九點的會議》：江南陸家繼承人、家族集團副總裁，工作地點在玩家公司隔壁大樓；不是男公關或模特兒。可以準備早餐、交代出門時間、詢問玩家是否留在家，但初識階段不會隨意開放住處。

## 四、陸沉川示範事件（僅在實際留宿後）
條件：玩家自願在陸沉川住處過夜；已建立私人聯絡；隔日陸沉川確有 09:00 會議；無其他衝突排程。
07:42 陸沉川：「醒了？」
間隔後：「早餐在廚房。」
「我九點有會議，妳不用跟著早起。」

玩家選項及各自不同回覆：
A「你每天都這麼早起？」→「工作日差不多。週末沒這麼準時。」→可延伸工作與作息。
B「你做了什麼早餐？」→「吐司、煎蛋。咖啡還沒煮，妳要喝再開。」→可延伸早餐偏好。
C「那我再睡一下，等你出門。」→「嗯。門不用反鎖。」→保留玩家仍在他家的位置狀態，之後才可觸發 11:26「醒了嗎？早餐有吃？」。
D「我也差不多該回去了。」→「好。我送妳到樓下。」→玩家確認離開後更新位置；不得再觸發留在他家的訊息。

每個選項必須接續玩家上一句，選項選定後立即移除舊選項；NPC 的下一輪問句需有新回覆集合。不得在同一回覆後殘留不相干選項。

## 五、關係差異
- 床伴：隔日可能客氣、尷尬、自然或想延續相處；不自動認定戀人。
- 曖昧：可以試探下次見面，不擅自宣告交往。
- 正式戀人：可有較自然的共同生活安排，仍尊重彼此行程。
- 秘密情人：可有隱瞞與嫉妒的後果，但第三人須有合理資訊來源才會懷疑。
- 冷戰或衝突：早晨可能需要談清楚、暫時分開或安靜離開，不能強制甜蜜收場。

## 六、持久化欄位建議（與現有 schema 合併，避免重複）
overnightEventId、hostCharacterId、inviterId、acceptedAt、arrivedAt、overnightLocation、nightChoices、consentHistory、sleepArrangement、morningEventId、morningChoice、departureAt、playerLocation、followUpMessageIds、relationshipSnapshot、knowledgeByCharacter、photoAssetIds、completedAt。
所有日期以遊戲時間記錄；存檔恢復後不可重播已完成選項、重複發送訊息或重複增加懷疑值。

## 七、測試驗收
1. 原過夜入口、床伴、轉正門檻、秘密關係、懷疑值及照片流程不退化。
2. 五位角色都有可觸發的不同早晨劇情。
3. 拒絕過夜、未赴約、提前離開時不產生虛假的共同早晨。
4. 選 C 留在陸沉川家，11:26 訊息依時間送達；選 D 離開則不觸發。
5. 未讀聊天室時 NPC 仍按排程傳訊。
6. 每一個玩家選項都有語義相符的 NPC 回應，且舊選項清除。
7. 同時多位角色聯絡時，位置、知情範圍與時間線一致。
8. 舊存檔可讀取，既有手機 KKT、照片、通知、日曆功能不被破壞。
9. 不宣稱不存在的照片已接入。
10. 完成程式實作、回歸測試後才可標示「功能完成」。
