# 角色視覺記憶庫｜生成與一致性規範

適用：《磚2》B 版及後續角色視覺創作。每一名角色**第一次由作者確認外貌後**，建立 `stories/ambiguity-b/visual-memory/<角色英文ID>.json`，後續生成同角色的聊天照片、Instagram Story、Instagram Post、角色卡與劇情照片，都必須先讀取該檔與它指向的**實際參考圖**，不能只依角色姓名重新生成。

## 單一來源與權威順序

1. 作者最新**明確確認**的設定及原始參考圖片（尤其五視角、五官、髮型、身材和表情）。
2. 本庫該角色 `status: locked` 的固定外觀與錨點圖（`referenceImages`）。
3. 對應角色文件與已確認的服裝、拍照偏好、日常場景。
4. 過去生成的照片僅作輔助風格參考；若和原始人物圖不同，以原始人物圖為準。

**重要**：名字、文字描述、圖片 URL 字串**無法自動讓圖像模型看見參考圖片**。生成時必須實際將參考圖提供給能接受圖片的生成工具；若當次無法取得參考圖，必須坦白標註「尚未完成視覺參考」，不得宣稱精準延續同一人物。已有的 GitHub 圖片也不得在未取得圖像內容的情況下虛稱「已對照」。

## 每位角色第一次定稿流程

1. 取得作者明確定稿的參考圖片，保存原始圖片或可存取的副本；記錄檔案路徑、版本、雜湊及授權／來源。沒有可存取圖片時，狀態只能是 `reference-pending`。
2. 記錄不可隨意變更的外觀：臉型、眼型與眼色、鼻唇、髮色髮型、身體比例、膚色及辨識特徵；同時記錄五視角與表情基準。
3. 記錄日常穿搭（核心輪廓、配件、可接受變化與禁用錯誤）；避免每天穿同一件，但保持人物風格。
4. 記錄拍攝習慣（誰拍的、角度、焦段感、光線、色溫、手持瑕疵、是否使用濾鏡）及角色平常會出現的生活場景。
5. 指定用途 `chat`、`instagram-story`、`instagram-post`，連結其相對資料夾；確定內容會出現在哪裡，不能把公開 Story 混同私訊。
6. 只在作者**更新外觀定稿**時替換錨點圖；一般生成不得偷偷重設臉、身高比例、髮色、人格或身分。

## 每次生成的強制檢查

- [ ] 已讀該角色的 locked 視覺檔，並實際調用其中可存取的參考圖
- [ ] 生成同一個人：五官、髮型、骨架、配件基準一致
- [ ] 穿搭在指定服裝範圍內，場景符合當天課業、工作、交友與生活節奏
- [ ] 視角符合拍攝者：本人拍的第一人稱照不可以無緣由出現第三人替他拍的全身照
- [ ] 風格符合渠道：聊天像順手傳；Story 即時；Post 稍有選片但不變成商業廣告
- [ ] 圖片標註角色 ID、用途、情境、檔名、來源錨點版本、是否上傳與是否接入劇情
- [ ] GitHub 提交後必須附**實際資料夾連結與 commit 連結**；未成功不得謊稱提交

## 狀態規則

- `reference-pending`：角色外貌尚未確認或參考圖不可取用；不可視為已鎖定。
- `locked`：作者已定稿且至少一張可實際取用的圖片參考及具體人物特徵已保存。
- `revision-needed`：作者要求重設形象，待新參考圖定稿。
- 已鎖定不代表每張生成圖會自動一致；每張仍需依圖片比對與人工複核。

記憶庫是**創作端資產**，不寫入玩家可見的好感度、劇情機密或遊戲存檔。修改角色視覺記憶本身不必無故變更 `story.json` 的 `revision`；只有實際變動玩家看到的素材／劇情資料時才按劇情規範更新。
