# 《磚3》角色照片專案交付規範 v1

本文件配合 `docs/brick3-photo-events-v1.json`。圖片採外部生成、玩家手動上傳；現有角色照片事件已由 `scripts/brick3-photo-events.mjs` 在建置時轉成 KKT 及相簿原生劇情節點。新增事件仍須有對應的劇情錨點，不會只靠在 JSON 填一筆就無條件出現。

## 交付步驟
1. 每個角色使用獨立的圖片生成專案，承襲角色固定外貌與現有情境，不可換臉。
2. 專案先檢查最新劇情/玩家選擇/人物日程；沒有來源時只能產出候選場景，不可聲稱事件已發生。
3. 每次輸出圖片 **連同** 同名事件配置片段，描述 `eventId`、`trigger`、`message`、`choices`（4 項）、`images`、`albumUnlock`、`visibility`、`nextEvents`。
4. 依 `{characterId}_{scene}_{shot}.webp` 命名，例如 `pei_zhiyu_dinner_chat_01.webp`；同名素材放 `public/story-photos/{characterId}/`。
5. 同一事件若新增影像，更新 `docs/brick3-photo-events-v1.json` 並提交同一分支；需要使用者/具寫入權的 GitHub 連接功能才能真正提交，不可只在文字中宣稱已提交。
6. 圖片由使用者自行上傳。若實際輸出不是 WebP，先轉成 WebP，不能只改副檔名。
7. 圖片完成後但尚未上傳時，允許劇情文字正常顯示，缺圖不崩潰；只有讀到實際存在的素材才展示圖片。
8. 程式已接入目前配置的事件、四選項分支與相簿解鎖。新增照片只要檔名及路徑完全符合現有事件，就可在上傳並完成 Pages 建置後於正確劇情顯示；新增**劇情事件**時，仍須更新配置與觸發錨點。

## 時序與自主性
- NPC 該傳的訊息即使玩家沒打開聊天室也正常排程送達。
- 玩家拒絕邀請或尚未抵達現場，不可解鎖「玩家已出席」照片。
- 玩家答應吃飯不等於答應親吻、牽手、留宿或復合。
- 玩家相簿只收錄玩家確實取得或拍攝的照片，不把 NPC 的私人照片強行加入。
- 私人照片不得不合理流入其他人物的視野；角色未知資訊不得憑空得知。
- 相片視角要有持有者/拍攝者/取得途徑；不能產生無人拍攝的「第三人稱紀錄照」卻假裝是手機私人照片。
- 重複生成須使用新 shot ID，已發布事件素材不可無聲替換導致存檔失效。

## 驗收條件
事件與資產 path 一致，四個選項可點擊且影響後續狀態；邀請被拒絕不解鎖到訪相簿；聊天未開啟亦可發訊；缺圖顯示降級；讀取舊存檔不重播已完成事件；跨日保留狀態；回滾後不污染其他分支。

## 已接入的執行路徑（2026-11-05）

`src/schema.ts` 驗證本機圖片路徑；`src/storyPhotoAssets.ts` 檢查 WebP 是否實際已發佈並處理 Pages 基底路徑；`scripts/story.mjs` 讀取配置並經 `scripts/brick3-photo-events.mjs` 轉為事件；`src/vendor/mymy/Apps.tsx` 使用劇情四選項；`src/Phone.tsx` 在 KKT、相簿前過濾缺圖素材。此功能不會在遊玩時動態呼叫圖片 AI。第五男主陸沉川已由 `scripts/brick3-v7-lu.mjs` 的 V7 SE-004 可拒絕入場、公開攝影再次見面、明確交換聯絡流程接入；玩家未取得私人聯絡前，其 KKT 及私訊照片維持隱藏。

## 好感度重複邀約 v1（已接入程式）
- 《磚3》現在會根據隱藏的各角色 `*_attraction`（0–100）與遊戲內時間，自主嘗試邀約；**不需要玩家開啟聊天室**。玩家每次選擇對話會帶來一次性的隱藏好感度變化；拒絕不會被強制判定為永久失去機會。
- 每個活動至少好感度 30 才能開始邀約；若玩家在 30 拒絕，需達 40 才可能再問；在 60 拒絕，需達 65 才可能再問。60 以下每 10 一階，60 以上每 5 一階；再次邀約也必須經過至少 3 小時遊戲內冷卻。到達門口仍可以取消，不會獲得照片。
- 玩家接受邀約並**明確選擇實際抵達**後，只解鎖一張該活動的相簿照片，標記永久完成；即使後來好感度再升高，也不會重複邀約同一個已完成活動。
- 活動完成 18–72 個遊戲內小時後，男主可能在 KKT 傳來一次隨機的延伸訊息，並附上一張**由他拍攝的獨立照片**。這張男主照片是聊天附件，不會自動匯入玩家相簿。若圖片尚未上傳，仍會顯示可以單獨理解的回訪文字，不會破圖。
- 目前有五名角色各一個活動，詳見 `docs/brick3-repeat-invitations-v1.json`。陸沉川額外要求玩家已同意交換私人聯絡方式。新增活動時，請在此配置加上台詞、事件圖片、回訪圖片；同一事件不要重複編列多張玩家相簿圖片。
- 這些活動完全沿用 FoundPhone 手機介面與 KKT 畫面。圖片仍由使用者自行產生、轉成真 WebP 並上傳到各人的 `public/story-photos/` 目錄，GitHub Pages 重新建置後便會在對應進度出現。
