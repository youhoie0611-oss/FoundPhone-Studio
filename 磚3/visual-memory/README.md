# 《磚3》角色視覺記憶庫

此資料夾僅適用於《磚3》。各角色**第一次由作者確立外貌**時，需建立獨立視覺記憶，之後每次生成私訊照、Instagram Story、Instagram Post，都先參照**該角色已核准的實際人物圖及記憶檔**，不得只以名字重新抽取人物長相。

## 來源與優先順序

1. 使用者在當次／最新對話**明確確認**的人物參考圖；如有新版，更新版本、雜湊、路徑，舊圖留作歷史，不自動覆蓋。
2. `registry.json` → `characters/<姓名>/profile/visual-memory.json` 所記錄的目前核准特徵、穿搭、拍攝慣性與生活場景。
3. 《磚3》的最新角色人格及已發生事件。不可把其他版本的人物核心、示意圖標籤、待選場景當成最新劇情事實。
4. 新劇情允許衣服、髮型整理程度、角度、情緒、光線與背景自然變化，但不可偷偷換臉。

## 一位角色首次確立外貌時

- 保留原圖及其尺寸、原檔名、SHA-256、Git blob SHA、核准日期及版號；原圖放在該角色 `profile/reference/` 目錄。
- 設定四類記憶：**固定五官與髮型、常見服裝、本人拍攝習慣、合理的生活場景**。
- 將「已確認事實」和「僅供產圖參考的場景建議」區分，不擅自新增養寵物、同居、約會歷史等情節。
- 在 `registry.json` 登錄這位角色；未確立外貌者保留 `not_registered_in_zhuan3_visual_memory`，不得擅自分配別人的臉。

## 每次生成前必須執行

1. 以角色 ID 查 `registry.json`。若沒有已核准參考圖，先取得並核准圖檔。
2. 讀取這位角色的 `visual-memory.json`，再**實際載入最新版參考圖片的像素**。只看文字或只讀路徑不算已引用。
3. 檢查固定五官、黑髮層次／眼鏡等個人特徵、生活日程與真實拍攝視角。自拍通常由本人持機或鏡前拍攝，第三人稱須有合理攝影者。
4. 指定照片唯一主要用途：KKT 私訊、Instagram Story 或 Instagram Post。根據該角色已建照片資料夾分類並保存。
5. 生成後記錄 photoId、人物、場景、拍照時間、檔名、GitHub 資料夾連結、實際提交狀態／commit，及對應劇情事件。相同 photoId 重用原圖，不得重生另一張冒充已發生事件。
6. 明確拒絕、封鎖、私訊可見權限及已發生劇情須優先遵守，不能因照片規則而覆蓋玩家選擇。
