# 《磚2》祁野專屬照片生成與傳送規則 V3.0

**狀態：作者於 2026-11-04 確認；祁野照片企劃的最高版本規範。**

本文件規範「作者生成／挑選遊戲素材」及「單機遊戲透過事件使用既有圖片」兩個層次。單機執行時應播放已保存的素材，**不是在玩家打開聊天室時即時重新生成圖片**。正式故事的事件引擎仍需另行整合，不能將本文件被提交視為功能已實作。

## 一、角色基本設定與核心定位

- **角色**：祁野；**年齡**：23 歲；**身分**：家境優渥的祁家次子。
- **性格**：張揚、直球、叛逆、好勝，有自己的原則；**興趣**：籃球、街頭運動、攝影、設計。
- **照片風格**：隨性惡犬型；**核心**：「想拍就拍，想傳就傳」。
- 祁野偶爾刻意耍帥，也會搞怪、狼狽、疲憊、安靜；不是只會耍帥的戀愛角色。
- 他有自己的朋友、家庭、興趣、生活與情緒，不會像沈硯舟一樣慣於分享所有小事。
- 每張出現祁野本人的照片必須使用已確認的 `assets/characters/qiye/visual-memory.json` 及**真正的**人物參考圖，不得只用「祁野」重新創造另一張臉。

## 二、長期照片題材參考權重

| 題材 | 權重 |
| --- | ---: |
| 籃球、街頭運動及其他活動 | 30% |
| 自拍、穿搭及個人近況 | 25% |
| 朋友聚會、外出活動 | 20% |
| 攝影、設計及個人作品 | 15% |
| 食物、風景及生活隨手拍 | 10% |

以上**僅是長期參考權重**，不是每日配額或執行時強制機率；應優先採信當天行程、事件、情緒、環境及拍攝動機。可以一整天完全不拍，也可以一次活動拍多張。禁止為湊比例製作無關照片。

## 三、五種自拍狀態

1. **耍帥**：鏡子、出門穿搭、側臉、運動後、戴耳機，偶爾特意挑好角度；知道自己好看，但不是每張都刻意展現魅力。
2. **隨性**：沙發、飲料、街上、球場邊、剛睡醒、車內休息、無聊的普通自拍；不一定有特殊意義。
3. **搞怪**：奇怪低角度、極近鏡頭、嫌棄表情、朋友互相惡搞、被朋友拍到的怪表情；祁野不能永遠冷臉高冷。
4. **狼狽**：打球流汗、亂髮、熬夜疲倦、運動後坐地休息、設計工作後疲態；不可刻意性感或曖昧化。
5. **安靜**：發呆、不笑、看窗外、獨處休息、低落時普通自拍；不應每張都陰暗、黑白或憂鬱風。

## 四、拍攝語言與手機感

- 可有低角度、側面、不對稱構圖、鏡子自拍、偶爾廣角。
- 運動容許自然動態模糊；容許手震、失焦、逆光、裁切不完美或人物偏離中央。
- 不過度磨皮，不使用不合理的攝影棚光線。
- 祁野懂攝影，**有時**可拍到好構圖和好光影；但須區分「攝影作品」與「普通手機隨拍」，不能每張像專業時尚寫真。
- 自拍／第一人稱照片應符合鏡頭與手部的物理位置；若是第三人稱鏡位，須有真實同行 NPC 或其他合理拍攝者。

## 五、情緒與照片連動

| 情緒 | 可以出現的照片及分享行為 |
| --- | --- |
| 開心 | 贏球、得意自拍、聚會、新買的東西、完成的設計；可能主動分享並帶玩笑或得意 |
| 興奮 | 某次活動可短時間連拍或傳多張，例如球場照再補同行 NPC 幫拍照；不能每次固定連傳 |
| 平靜 | 一般自拍、穿搭、食物、街景、草圖、房間一角；無須特別意義 |
| 無聊 | 可以突然傳莫名其妙的照片、抱怨幾句，也可傳完不繼續聊天 |
| 疲憊 | 運動後、地上的鞋、凌亂工作桌、未完成設計、休息狀態；文字通常較短 |
| 生氣 | 拍攝及分享意願可能降低；照片與當下事件相關，不能固定打架、破壞、危險行為 |
| 難過 | 空球場、夜路、面無表情自拍、房間一角、相關物品；可嘴硬或直說低落，不每次套相同否認→坦白公式 |

情緒不是固定圖片模板；同情緒的反應可依具體經歷變化。

## 六、與其他 NPC 外出時的拍攝者分布

**只對已確認有共同外出、且適合拍照的事件使用下列長期參考比例：**

- **50% 自己拍**：自拍、球場、街景、食物、朋友正在做的事、有趣物件。
- **20% 同行 NPC 幫拍**：祁野打球、走路、聊天、設計、大笑、休息或沒注意鏡頭；需記錄真實同行者作為攝影者。
- **30% 與同行 NPC 合照**：搭肩、比手勢、搞怪、大笑或不看鏡頭；同行 NPC 的身份、關係及視覺記憶須一致。

這不是每次外出必拍的配額。禁止生成故事中不存在的朋友或未出現的拍攝者；禁止任意改造既有 NPC 外貌。**不能生成玩家與 NPC 的合照。**

## 七、主動拍照與傳送

祁野可以在玩家沒有開啟聊天室時，自主拍照及主動傳照。決策要同時參考：

1. 當天行程；2. 事件；3. 情緒；4. 分享動機；5. 玩家關係；6. 當下是否忙碌；7. 已發生對話及事件。

- 可突然傳一張、只加一句文字、傳完繼續生活、隔一段時間補充、因想到玩家而分享、為炫耀成果而分享。
- 不設每日固定傳照數；玩家開聊天室不會觸發強制新照片。
- 祁野不如沈硯舟頻繁分享細節；長期沒傳也應自然。
- 角色忙碌、延遲回覆、取消分享或決定不傳，皆是合法結果。

## 八、傳照後的對話節奏

- 自然、隨性、直球，偶爾挑釁，但不是永遠短句、永遠撩或固定嘴臭。
- **球場例**：「今天手感不錯。」→［球場照］→玩家問「你贏了？」→「廢話。」／「最後那球差點沒進。」若玩家追問再正常說明過程。
- **搞怪例**：「操。」→［被朋友拍得狼狽的照片］→「這什麼鬼角度。」玩家可笑、關心、追問、轉移話題，四種反應都要有對應回覆。
- **設計例**：「昨天弄到三點。」→［作品照］→「總算改完了。」認真詢問時要具體回答設計思路、修改與困難。
- 不要反覆用「喂」「怎樣」「不然呢」，不要無視玩家問題，不要一次倒出大量台詞；回合需要停頓、可問可答。
- 玩家忙碌時應結束或暫停；玩家沒回覆，祁野仍過自己的生活。

## 九、關係階段與照片內容

- **剛認識**：不穩定分享，活動、設計、運動居多，少數普通自拍，玩笑適量，不突然分享過分私密內容。
- **逐漸熟悉**：可較常主動，穿搭、自拍、聚會、更多興趣，可能延伸話題。
- **關係親近**：可以分享疲態、狼狽、家庭或生活困擾，不只得意面，對話更自然。
- **曖昧**：偶爾挑好看的自拍，較在意玩家反應或藉照片玩笑，但不能每次刻意撩；不得變控制型人格。
- **交往**：自然分享剛醒、運動後、休息等狀態，偶爾為玩家特地拍照；仍維持獨立朋友圈、工作與個人生活。

所有階段都不強制戀愛進展，不擅自替玩家決定感受。

## 十、照片連續性與永久事件記憶

每張照片生成前後須核對：五官；髮型髮色及體態；同一天衣服；同活動場景；同行 NPC 身份及臉；時間與光線；事件因果；可行鏡位；不可把同一照片重生另一個版本。

每張必須追蹤以下欄位（若事件尚未觸發，欄位可為 null）：

- 唯一照片 ID、拍攝者、入鏡人物、拍攝時間、拍攝地點。
- 關聯劇情事件、祁野當下情緒、穿搭狀態。
- 是否已**拍攝**、是否**選擇分享**、是否**實際傳送**（三項獨立狀態）。
- 實際傳送時間、對應聊天室訊息、已讀／未讀狀態。
- 保存原始素材檔案路徑，不因再次點開聊天室而重新生成或改寫。

## 十一、全角色共通的單機遊戲限制

1. 玩家只透過遊戲提供的劇情**選項**回 NPC。
2. 玩家不需要用真實相機，也不需要上傳任何圖片。
3. 不生成玩家與 NPC 合照，NPC 也不會向玩家索照；**不做照片交換功能**。
4. NPC 照片由**故事事件與角色狀態**推動；聊天室不在前景也可自主送照。
5. 未讀圖片及訊息留存，玩家稍後進入聊天室只能看到已發生的歷史，不會被重置或改寫。
6. 以上對祁野與其他角色都適用。

## 十二、執行流程（企劃規範，尚待遊戲整合）

1. 讀時間和位置。
2. 讀活動、日程。
3. 讀情緒與故事狀態。
4. 判斷拍攝動機（不適合時不拍）。
5. 決定題材。
6. 決定自拍／景物／同行 NPC 幫拍或合照。
7. 讀祁野視覺記憶及實際參考圖。
8. 讀同行 NPC 視覺記憶。
9. 核對服裝、人物、場景、時間連續性。
10. **素材製作階段**生成圖片並永久保存；**遊戲執行階段**引用已存圖片。
11. 判斷是否要分享（可以不分享）。
12. 如要分享，安排合理送達時間。
13. 製作祁野本人語氣的聊天訊息。
14. 保留未讀狀態。
15. 玩家四選項後按照選擇自然回覆。
16. 保存事件、圖片、訊息與角色記憶。

## 十三、禁止事項

- 不得隨機換臉、每張耍帥、全部專業寫真、固定每日拍照數、脫離日程情緒。
- 不得生成不存在的同行者、玩家與 NPC 合照，或讓 NPC 向玩家討真實照片。
- 不得忽略玩家選擇、覆寫玩家看過的照片事件、重複生成已有照片。
- 不得讓豪車、名錶、豪宅成為祁野所有照片的標配。
- 不得將祁野固定為霸道、挑釁、高冷的單一人格。

## 十四、最終照片定位

祁野是一個有朋友、有家庭、有興趣與生活節奏的 23 歲年輕男性。他的照片可以帥、好笑、活躍、普通、狼狽或沉默。他不為了維持戀愛互動而強迫自己拍照，也不因玩家而停下生活。

**核心：隨性惡犬，想拍就拍、想傳就傳；真實生活優先於刻意營造魅力。**

### 素材位置與實作邊界

- KKT 私訊：`assets/characters/qiye/chat/`
- Instagram Story：`assets/characters/qiye/instagram/story/`
- Instagram Post：`assets/characters/qiye/instagram/post/`
- 視覺記憶：`assets/characters/qiye/visual-memory.json`
- 角色設定：`stories/qiye/character-profile.json`
- 照片事件企劃：`stories/qiye/photo-events.json`
- 結構化規則：`stories/qiye/photo-policy-v3.json`
- 預設可遊玩故事：`stories/template/story.json`

本規則文件及 JSON 是**作者資料**，不是故事編譯器已支援的事件 JSON schema。要使照片按規則在遊戲中送達，需要將已上傳的圖片與事件編入正式故事並通過 `npm run story:validate`、`npm run story:test`、`npm run build` 驗證。單機遊戲不應在使用者端呼叫圖片生成模型。
