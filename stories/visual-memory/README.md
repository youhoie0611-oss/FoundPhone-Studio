# 《磚2》角色視覺記憶庫

這是**圖片生成與故事創作的視覺來源檔**，不是玩家存檔、AI 自主記憶，也不會自行替換遊戲圖片。建立角色外貌後，人物身份及參考圖應被固定，不得僅憑名字再次隨機生成人臉。

## 資料來源與優先級
1. 玩家**最新明確確認**的正式外貌與更改。
2. 本目錄每位角色的 `characters/<id>.json` 中已鎖定的參考圖、外貌、服飾與拍攝習慣。
3. 原有角色核心設定與已發生的劇情事實。
4. 新情境可變的服裝、拍攝位置、情緒與日常事件。

## 生成流程（必須）
1. 先開 `index.json`，按明確 characterId 找到對應角色檔，不能從名字猜圖。
2. **實際載入** `identityReference.repositoryPath` 的高畫質參考圖作為生成圖片的身份依據，再讀 `approvedAppearance` 和 `photoHabits`。只有 JSON 文字而沒有讀到圖時，不可聲稱已完成視覺一致性核驗。
3. 如果是角色自己拍的照片，拍攝視角必須合理：手機握持位置、可能的手或袖口、自然光線、器物與場景；避免第三人稱攝影師或棚拍視角。
4. 每次生成先決定用途（KKT、Instagram Story、Instagram Post）；保持相同角色的習慣，但避免所有照片一樣的光線或角度。
5. 檢查髮型、臉型、穿搭細節、環境、角色擁有的物品、事件時間與故事因果，確保不使用未確認的背景。
6. 成品要標示分類、檔名、圖片所在路徑、GitHub 資料夾連結，若提交成功附 commit；**不能把已生成誤說成已上傳或已在遊戲生效**。

## 維護規則
- 新角色第一次獲玩家確認後，建立獨立 JSON、保留正式參考圖的原始高畫質資產，記錄 Git blob SHA 與當時批准依據，並加入 `index.json`。
- 只有玩家明確改造外觀時才更新鎖定圖與 SHA，並核對其他角色資料；不得擅自改寫原本外貌或人物身分。
- 如果沒有已核准人物參考圖，標記 `pending_visual_confirmation`，不可假設長相。
- 參考板上的**文字標籤不一定是人物核心設定**。裴知聿使用者確認的照片舊版標有沈硯舟，這不代表裴知聿變成沈硯舟。
- `scripts/validate-visual-memory.mjs` 可檢查視覺記憶索引、參考圖是否存在及 Git Blob 雜湊是否遭意外替換；通過資料驗證不代表生成後視覺品質已由人眼通過。
