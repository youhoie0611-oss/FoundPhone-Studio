# 第176–177章｜玩家輸入優先與無保證結果

> 全遊戲互動的高優先級規則；適用於固定選項、第四選項【玩家自定義】、訊息、行動、社交平台與跨日事件。此文件為規格，不代表引擎已完成。

## 第176章｜玩家輸入優先
1. 先保留玩家原始輸入（含原文、時間、目標對象、指定行動），再解析意圖及可執行前置條件；不能偷偷改寫成另一個行動、情緒或關係立場。
2. 對可執行行動先嘗試執行，產生可觀察的世界狀態變化，再按 NPC 的知情範圍、性格、日程與既有計畫生成反應。
3. 對不可執行行動，明確呈現受阻原因或合理失敗結果；不可默默套用最接近的固定選項。
4. 玩家輸入「拒絕邀約」不得轉為答應；「封鎖」不得降級為不回覆；「不想復合」不得解讀為欲拒還迎；玩家未表達的情緒不得代寫。
5. 行動優先是處理順序與忠實度規則，不等於玩家能操控其他角色的意志或取得不具備的權限。

## 第177章｜無保證結果
1. 玩家可能失敗、被拒絕、錯過機會、失去 NPC、關係惡化或遭遇不可逆後果。
2. NPC 可依其目標、知情範圍與界線拒絕玩家、改變計畫、退出關係；不因玩家選擇「正確」台詞就必然被說服。
3. 時間敏感事件與已發生的後果不可為迎合玩家而任意重置；修復可能耗時、失敗或永遠無法完成。
4. 不設說教式懲罰或強制悲劇；成功與失敗均須有可追溯的世界條件與人物邏輯。

## 建議處理管線
rawPlayerInput → intentAndTarget → actionPreconditions → attemptedAction → worldStateDelta / failureReason → NPCKnowledgeFilter → NPCReaction → consequenceLog → save。
原文必須完整保存；無法解析時先澄清，不可偷換行動。

## 驗收
- 自定義「拒絕」不會被替換成預設曖昧回覆。
- 自定義「封鎖」改變實際聯絡權限，而非只改變對話文本。
- 玩家嘗試邀約時 NPC 可以拒絕。
- 不可執行的行動會回報失敗，不會假裝成功。
- 不可逆旗標與跨日事件持久保存；重新載入不重置。
- 玩家輸入原文、實際行動結果與 NPC 反應可追溯且互相區分。

本章與第50–57章關係自由、第116–122章資訊差、第123–136章自主世界與不可逆後果、第147–154章導演機制及第161–165章通訊權限共同適用。
