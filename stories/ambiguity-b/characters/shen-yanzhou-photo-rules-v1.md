# 《磚2》沈硯舟專屬照片生成規則 V1.0

> 狀態：作者正式確認／生效日 2026-11-04。此文件屬角色創作規範；`story.json` 為實際已實作劇情。**規範並不等於每項動態機制都已程式化**。創作與遊戲內容變更須分別驗證。

## 一、角色核心設定

沈硯舟，24 歲，大學生。開朗、活潑、真誠、溫暖、細心、有原則，黃金獵犬系 70%＋杜賓犬系 30%。**聒噪小狗、很愛自拍、喜歡分享生活**，有課業、運動、攝影、朋友聚會及獨立休閒活動。與玩家在活動中認識，感情自然發展。外貌必須使用 [專屬視覺記憶庫](../visual-memory/shen-yanzhou.json) 與其中指向的實際參考圖，禁止每次只靠姓名重新生成。

**核心**：他會自己主動記錄及分享人生，不是為了討好玩家才拍照。拍照 ≠ 一定傳給玩家；分享 ≠ 要求回傳。

## 二、照片生成風格：真實手機隨手拍

- 現場自然光、室內燈光、真實手機成像；可有手震、模糊、失焦、逆光、雜物、凌亂背景及路人。
- 不需人物置中，自拍角度可以隨意；不得過度磨皮、商業棚拍光線、不合理電影級效果或千篇一律的精修。
- 因他喜歡攝影，**部分**照片可構圖良好、有光影意識，但不是每張照片都是藝術創作。
- 同一個人長期拍攝的痕跡：喜自拍、記錄趣事、校園與運動、朋友日常，偶爾搞怪角度、失敗照也敢分享；開心時較活潑，低落時較安靜。

## 三、照片類型比例（長期建議，不是每日配額）

| 類型 | 長期建議權重 |
| --- | ---: |
| 自拍 | **40%** |
| 日常隨手拍 | **25%** |
| 朋友、運動及活動 | **20%** |
| 風景與攝影作品 | **15%** |

實際**當天劇情、情緒、場景和拍攝機會優先**於比例；不強制每一組、每一天配滿。球賽日自然以運動、球場、朋友為主。

## 四、自拍專屬規則

- 他不需要特殊理由便能自拍，也經常想分享：睡醒亂髮、課桌趴著、打球滿頭汗、吃飯、出門穿搭、朋友鬼臉、搞笑失敗照、疲倦發呆及自然大笑。
- 角度允許：正面、高低角度、側臉、鏡子、半張臉、伸手、躺／趴著、近距離怪角度、與朋友同框；務必符合真實手機鏡頭與手臂持機方式。
- 表情：露齒笑、微笑、鬼臉、比耶／比讚、鼓臉、無奈、疲倦瞇眼、發呆、沒笑、偶爾認真帥氣；**不得反覆同一姿勢與表情，也不能全是完美帥照**。
- 若畫面有他的臉，必須與已鎖定五視角參考相符；沒有臉的照片仍要保持相同拍攝習慣與裝備。

## 五、情緒與生成表現

| 情緒 | 相片和訊息呈現 |
| --- | --- |
| 開心 | 自拍與分享較多、表情活潑，可能連拍，接著聊照片趣事 |
| 興奮 | 可連續幾張，偶有動態模糊，立即分享、分段補充事情 |
| 平靜 | 普通自拍、食物、校園、窗外，不需特別意義 |
| 無聊 | 做鬼臉、拍課桌窗外小東西，可能主動開聊 |
| 疲憊 | 趴桌、運動後、深夜課業凌亂，自嘲文字 |
| 難過 | 可能減少自拍、表情不笑、拍空教室／窗外／夜街，不強制黑白；話少，視信任決定坦白 |
| 生氣 | 拍照意願下降、可能僅拍事件物品；訊息簡短，可能想暫時獨處，不擺拍博取關注 |

「聒噪小狗」**不代表永遠開心**；情緒須由劇情推導，不可強制產出照片。

## 六、與他人外出的照片

僅在有**實際同行人物與合理拍照機會**時，建議使用：**本人拍攝 50%／同行者幫拍 20%／與同行者合照 30%**。這是條件式長期權重，不可覆蓋真實事件。

- 他人幫拍須有人確實同行並願意拍，會有大笑、走路、運動瞬間，也不必每張正臉。
- 合照可自拍、比手勢、搭朋友肩膀；同行者臉部需引用已確立角色視覺庫，不得隨機換人。
- 人物間距和動作須符合彼此關係；不得無故生成情侶式親密姿勢。
- 玩家**未參加活動**不得生成玩家合照；玩家**拒絕拍照**不得強制生成。肖像公開另需遵守劇情中的授權界線。

## 七、拍攝／分享分離與主動傳送

- 不必玩家先開口、不必特殊節日；可傳一般小事，可能同一天不同時間傳照，遇到趣事想即刻分享，偶爾一次傳兩三張。
- **拍得多不代表全部傳給玩家**。合理決定「是否拍、是否分享、分享到哪裡」（KKT 私聊／IG Story／IG Post），尊重玩家已表達的不要傳照意願。
- 玩家沒點開聊天室，**已排定的傳送時間與通知仍須照常到達**；送達與是否被閱讀是兩件事。不回覆時可偶爾補一句，但不得無限洗版。

## 七之一、永久禁令：不得向玩家討照片

**不論剛認識、熟悉、親近、曖昧或交往，永遠禁止沈硯舟主動要求玩家傳自拍、生活照或任何私人照片。**

禁用示例：「換妳拍給我看。」「我都傳了，妳也要傳。」「拍一張給我嘛。」「妳今天長怎樣？」及以玩笑、撒嬌、交換、賭氣或施壓形式要求照片。

他可以問玩家是否**願意看他拍的照片**，或詢問是否**同意公開含玩家肖像的活動照片**；這不等於索取玩家傳照片。若玩家自願傳照，可以自然回應，**不得順勢追討更多**。

## 八、照片與對話節奏

沈硯舟傳完照片，通常還會主動補幾句、有趣吐槽，之後讓玩家有**自然的回覆與互動**。話多但不機械，不必每次問「妳覺得怎麼樣？」。

**合法排法要多樣：**「文字 → 照片 → 文字」「照片 → 文字」「照片 → 玩家回覆 → 接續聊」「文字 → 照片 → 照片 → 補充」「照片 → 短停頓 → 自嘲」。訊息的停頓與玩家選擇要真實；若玩家忙則停下，玩家玩笑則接梗，玩家關心則視情緒與信任程度答覆，沒新內容可自然結束。

參考口吻（不固定照抄）：

> 哈哈哈哈妳看
> 
> ［傳送風吹亂髮型的自拍］
> 
> 我剛剛差點被風吹走
> 
> （短暫停頓）我出門前明明還有抓頭髮欸
> 
> 算了，帥哥不需要髮型

**不可**只讓他「傳圖→固定問好看嗎→玩家答→劇情立即結束」。

## 九、關係階段

- **剛認識**：依然活潑、愛自拍、可傳校園／活動／運動／搞怪自拍，不突然分享過度私密資訊。
- **逐漸熟悉**：增加普通生活、疲憊或無聊自拍，願談更多私事。
- **關係親近**：更自然分享不修飾的畫面，信任足夠時才分享失落；能延續舊照片話題。
- **曖昧**：可能在意反應、用怪照逗人，但不油膩或控制。
- **交往**：自然分享近況，偶爾為玩家特別拍照，仍保有課業、朋友與個人生活。
- **永久禁令**：所有階段都不得向玩家索取照片。

## 十、連環照片分享

當同一場活動確實觸發多個拍照點，可以形成時間合理、由同一人記錄的照片序列。例如市集：14:10 出門自拍、14:35 有趣物件、15:20 朋友幫拍、16:00 食物。不是每次外出都要四張。

同一事件序列須同時滿足：**同活動、時間合理、穿搭連續（換衣有事件）、場景移動合理、同行者一致、課表／行程相符**。玩家未打開 KKT，已排程訊息仍按時送達。

## 十一、視覺記憶與素材唯一性

- 生成前讀取 [視覺記憶檔](../visual-memory/shen-yanzhou.json) 與真正可用的臉部定稿圖，檢查臉、髮、比例、服裝、活動連續、同行者、時間光線與文字。
- 每張圖應有穩定的 **photoId**、原始檔路徑、分類（`chat/`／`instagram-story/`／`instagram-post/`）、拍攝者、活動 `eventId`、拍攝／傳送時刻、連續序列編號及是否被遊戲引用。
- **同一照片再次出現時必須重用同一素材路徑**，不能重新生成換臉／換場景的另一版本。
- 既有素材登記於 [照片登錄表](./shen-yanzhou-photo-index.json)；未提交 GitHub 不可標示已上傳或已入劇情。

## 十二、生成與傳送前的執行檢查順序

1. 他現在在哪裡、在做什麼？
2. 情緒如何？
3. 這情境適不適合拍照？
4. 他會拍什麼？
5. 自拍／景物／他拍／合照哪種合理（比例不能壓過真實情況）？
6. 是否符合角色視覺記憶庫？
7. 他有理由想分享給玩家嗎？還是只存相簿或發 IG？
8. 當前關係與玩家界線允許嗎？**絕對不能要求玩家傳私人照**。
9. 應該何時傳？即時／延後／不傳？
10. 傳送後他會怎麼說？文字／圖片順序是否變化？
11. 玩家回覆後，他會如何自然接話或收尾？

不適合拍照時允許**完全不產生照片**。最終呈現是玩家逐漸熟悉他生活中的活潑、聒噪、喜歡自拍與偶爾安靜，而不是照片圖鑑展示。

## 實作及驗收註記

這份 V1.0 是後續內容生成的**強制創作契約**，不是引擎隨機生成器。當前遊戲實際含四張第一人稱景物照；它們仍可沿用，但不代表未來 40% 自拍權重已達成、所有 11 步決策都會於執行時自動運算或動態照片連環排程已完成。新增照片需按分類真實提交，更新場景後再執行 `npm run story:validate`、`npm run story:test`、`npm run build` 與手機預覽。未驗證時不宣稱完成。
